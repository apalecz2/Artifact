Open your icons folder to begin
Point it at app\src-tauri\icons. Every PNG, every layer inside icon.ico and every chunk inside icon.icns will appear here, rendered from the live design.

Requires Chrome or Edge (File System Access API).
After writing — checklist (from icon-regeneration.md)

1. Windows caches icons aggressively. Rebuild the cache, then restart Explorer if the taskbar is still stale:

ie4uinit.exe -show   then   taskkill /IM explorer.exe /F; start explorer.exe

2. Rebuild the app so the new icon.ico is embedded. Cargo does not watch the icons folder — touch tauri.conf.json first (e.g. (Get-Item app\src-tauri\tauri.conf.json).LastWriteTime = Get-Date) so build.rs re-runs, re-embeds the exe resource, and re-expands generate_context! (the runtime window icon). Then cd app && npm run tauri dev or build.

2b. The taskbar icon of the running app is a single image: Tauri embeds the first entry of icon.ico and sets it as the window icon. This tool always writes the 32×32 entry first for that reason.

3. Confirm tauri.conf.json → bundle.icon lists 32x32.png, 128x128.png, 128x128@2x.png, icon.icns, icon.ico.

4. The rebuilt icon.icns uses modern PNG chunks (icp4/icp5/ic07–ic14); the legacy is32/il32 RLE chunks are dropped — fine for macOS 10.7+.

5. The Windows taskbar draws the small (16–32 px) layers of the .ico embedded in the exe — that is where the Small / taskbar variant shows up.

Settings (variants, threshold, overrides) are saved to icon-studio.config.json inside the folder on every write, and to localStorage as you edit.
